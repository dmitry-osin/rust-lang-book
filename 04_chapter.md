### Глава 4. Функции и Замыкания

Представь, что твой код — это огромный завод. Если весь код написан сплошным текстом в функции `main`, это похоже на завод, где все рабочие, станки и детали свалены в одну огромную кучу. Работать в таком хаосе невозможно. 

**Функции** — это отдельные, изолированные цеха. В один цех (функцию) поступает сырье (параметры), там происходит работа (код), и на выходе мы получаем готовую деталь (возвращаемое значение).

#### 1. Функции: Параметры и Возвращение значений

Мы уже видели функцию `fn main()`, но давай создадим свою собственную.

Допустим, нам нужно часто вычислять цену товара со скидкой.
Чтобы создать функцию, мы используем ключевое слово `fn`, даем ей имя (в Rust принято писать имена в стиле `snake_case` — маленькими буквами через нижнее подчеркивание), указываем входящие параметры и то, что она должна вернуть.

```rust
// fn имя(параметр: Тип) -> Тип_возврата
fn calculate_discount(price: f64, discount_percent: f64) -> f64 {
    let discount = price * (discount_percent / 100.0);
    let final_price = price - discount;
    
    // Внимание на следующую строку!
    final_price
}

fn main() {
    let shoes_price = 5000.0;
    // Вызываем нашу функцию
    let to_pay = calculate_discount(shoes_price, 20.0);
    
    println!("К оплате: {}", to_pay);
}
```

**Главная фишка Rust: Возврат без `return`**
Посмотри на строку `final_price` в конце нашей функции `calculate_discount`. Заметил, чего там не хватает? Там **нет точки с запятой** в конце! 

В Rust любое выражение, после которого *не стоит* точка с запятой, автоматически становится результатом (выходом) из функции. Это очень лаконично и красиво. 
Конечно, ты можешь написать `return final_price;`, как в старых языках (и это нужно делать, если ты хочешь досрочно выйти из функции, например внутри `if`), но для возврата в самом конце так писать не принято.

#### 2. Блоки кода как выражения

В Rust почти всё является "выражением" — то есть чем-то, что вычисляется и выдает результат. Даже обычные фигурные скобки `{}`.

Ты можешь создать мини-цех прямо посреди другого кода:

```rust
fn main() {
    let radius = 5.0;
    
    // Мы открываем отдельный блок кода
    let circle_area = {
        let pi = 3.14159;
        // Переменная pi живет только внутри этих скобок!
        pi * radius * radius // Нет точки с запятой — значит блок вернет это значение
    };
    
    println!("Площадь: {}", circle_area);
    // println!("Пи: {}", pi); // ОШИБКА! Компилятор скажет, что не знает, что такое pi
}
```
Это отличный способ сделать код чище и изолировать временные переменные, чтобы они не болтались в памяти.

#### 3. Замыкания (Анонимные функции)

Обычные функции (`fn`) хороши, когда код большой и используется во многих местах. Но иногда нам нужна крошечная функция буквально на один раз. Писать для нее полноценное определение `fn` где-то далеко в файле — это как строить отдельный бетонный цех ради того, чтобы один раз забить гвоздь.

Для таких случаев существуют **Замыкания (Closures)**. Это "функции без имени", которые можно положить прямо в переменную.

Синтаксис замыкания отличается от обычных функций. Вместо круглых скобок для параметров используются вертикальные черты `| |`.

```rust
fn main() {
    // Создаем замыкание и кладем его в переменную add_numbers
    // Компилятор сам догадается о типах, нам не нужно писать их явно!
    let add_numbers = |a, b| a + b;
    
    // Вызываем замыкание точно так же, как функцию
    let result = add_numbers(10, 5);
    println!("Результат: {}", result); // Выведет 15
}
```

#### 4. Магия замыканий: Захват окружения

Почему замыкания так называются? У обычных функций `fn` есть жесткое правило: они слепы и видят *только* то, что им передали в параметры. Они не могут заглянуть в функцию `main` и взять оттуда переменную.

А вот замыкания — могут! Они могут "замкнуть" (захватить) в себя переменные, которые находятся рядом с ними. Представь, что замыкание — это рабочий с рюкзаком, который может брать инструменты, лежащие вокруг него в цехе.

```rust
fn main() {
    let tax_rate = 0.13; // Переменная в main

    // Замыкание "видит" tax_rate и использует его, хотя мы не передавали его в параметры!
    let calculate_tax = |salary| salary * tax_rate; 

    println!("Налог: {}", calculate_tax(100000.0));
}
```

#### 5. Тонкости под капотом: Трейты Fn, FnMut, FnOnce

*Это концепция для собеседований и глубокого понимания языка. Мы будем касаться её снова, когда перейдем к теме Памяти, но базу нужно заложить сейчас.*

Поскольку замыкания могут брать вещи (переменные) из своего окружения, компилятору очень важно знать, **как именно** они с ними обращаются. Для этого в Rust есть три категории (трейта) замыканий:

1.  **`Fn` (Только посмотреть)**.
    Замыкание просто читает внешние данные, ничего не меняя. Это самый частый и безопасный вид.
    *(Аналогия: рабочий просто посмотрел на чертеж, лежащий на столе).*

2.  **`FnMut` (Могу изменить)**. `Mut` от слова mutable (изменяемый).
    Замыкание берет внешнюю переменную и меняет её значение. Чтобы это сработало, сама внешняя переменная должна быть объявлена как `mut`.
    *(Аналогия: рабочий взял со стола бланк и заполнил в нем новые данные).*
    ```rust
    let mut click_count = 0;
    
    // Ключевое слово mut обязательно перед замыканием, так как оно меняет состояние
    let mut click_button = || {
        click_count += 1;
        println!("Нажато {} раз", click_count);
    };
    
    click_button(); // Выведет 1
    click_button(); // Выведет 2
    ```

3.  **`FnOnce` (Один раз и навсегда)**. `Once` переводится как "однажды".
    Это самый строгий вид. Замыкание забирает переменную себе **навсегда** (забирает владение). После того как такое замыкание отработает, внешняя переменная уничтожается, и её больше нельзя использовать в функции `main`. Такое замыкание можно вызвать только один раз в жизни.
    *(Аналогия: рабочий взял деталь со стола и навсегда встроил её внутрь сложного механизма. Деталь исчезла со стола).*

#### 6. Функция как параметр (Функции высшего порядка)

Поскольку в Rust функции и замыкания — это полноценные типы данных, мы можем передавать их внутрь других функций! Это позволяет создавать невероятно гибкий код.

```rust
// Функция do_twice принимает число и ЛЮБОЕ замыкание (или функцию), 
// которое принимает i32 и возвращает i32. 
// F: Fn(i32) -> i32 — это то, как мы говорим компилятору о типе замыкания.
fn do_twice<F>(number: i32, action: F) -> i32 
where 
    F: Fn(i32) -> i32 
{
    // Выполняем переданное действие два раза
    let first_result = action(number);
    action(first_result)
}

fn main() {
    // Создаем замыкание, которое умножает на 2
    let double = |x| x * 2;
    
    // Передаем замыкание double внутрь функции do_twice
    // Сначала 5 умножится на 2 (будет 10), потом 10 умножится на 2 (будет 20)
    let final_value = do_twice(5, double);
    
    println!("Итог: {}", final_value); // Выведет 20
}
```

Это основы функционального программирования. Когда мы дойдем до коллекций и итераторов (списков и массивов данных), мы будем использовать такие конструкции постоянно (например, чтобы отфильтровать список: "оставь в списке только те элементы, для которых вот это замыкание вернет `true`").
