### Глава 2. Инструментарий и Качество кода (Сразу пишем правильно)

В мире программирования есть рутина: нужно скачивать чужой код (библиотеки), указывать компилятору, в каком порядке собирать файлы, проверять ошибки и следить за красотой кода. В некоторых языках программистам приходится настраивать всё это вручную, тратя дни на конфигурацию.

В Rust философия другая: **всё должно работать "из коробки"**. Для этого у нас есть три главных помощника.

#### 1. Cargo: Твой прораб и менеджер пакетов

**Cargo** (переводится как "Груз" или "Грузовое судно") — это программа, которая установилась на твой компьютер вместе с Rust. Это менеджер твоего проекта. Ты даешь ему высокоуровневые команды («создай проект», «скачай библиотеки», «собери программу»), а он сам дергает "голый" компилятор `rustc` и делает всю грязную работу.

Давай забудем про ручное создание файлов и доверим дело Cargo.

**Создание проекта:**
Открой терминал и введи команду:
```bash
cargo new my_first_app
```
Cargo моментально создаст папку `my_first_app`. Если мы заглянем внутрь, то увидим такую структуру:
```text
my_first_app/
├── Cargo.toml
└── src/
    └── main.rs
```

Что это за файлы?
*   **`src/main.rs`** — это исходный код твоей программы (source). Cargo уже заботливо написал там стартовый "Hello, world!". Все твои файлы с кодом будут лежать в папке `src`.
*   **`Cargo.toml`** — это "паспорт" твоего проекта. Открой его в блокноте, и ты увидишь примерно следующее:

```toml
[package]
name = "my_first_app"
version = "0.1.0"
edition = "2021"

# Раздел с зависимостями. 
# Зависимости — это чужой код, который мы хотим использовать в своей программе.
[dependencies] 
```

В мире Rust сторонние библиотеки (например, код для генерации случайных чисел или создания веб-сервера) называются **Крейтами (Crates)** — буквально "деревянный ящик для груза", что отлично сочетается с названием менеджера Cargo. Когда тебе понадобится чужой код, ты просто впишешь название крейта в `Cargo.toml`, и при следующем запуске программы Cargo сам скачает его из интернета.

**Как запускать программу через Cargo?**
Зайди в терминале внутрь созданной папки (`cd my_first_app`) и используй эти три главные команды:

1.  **`cargo build`** — просит Cargo собрать программу. Он скомпилирует код и положит готовую программу (exe-файл) в скрытую папку `target/debug/`.
2.  **`cargo run`** — твоя самая частая команда. Она делает две вещи за раз: собирает программу (как `build`) и сразу же её запускает.
3.  **`cargo check`** — команда для быстрой проверки. Она проверяет код на ошибки, но *не тратит время* на создание финального файла программы. Во время написания кода программисты запускают `cargo check` сотни раз в день, чтобы просто спросить компилятор: «Я тут не ошибся?». Это работает в разы быстрее, чем `cargo build`.

#### 2. Rustfmt: Конец спорам о красоте кода

В программировании есть вечная проблема: каждый пишет код в своем стиле. Кто-то ставит фигурные скобки на новой строке, кто-то делает отступы пробелами, кто-то табуляцией. Когда программисты работают в команде, разный стиль кода превращает чтение в муку.

В Rust этот вопрос закрыт навсегда с помощью инструмента **`rustfmt`** (Rust Formatter).
Это программа, которая автоматически причесывает твой код под единый, официально принятый стандарт.

Представь, что ты написал код очень неаккуратно:
```rust
fn main()      {
println!   ("Привет");
      let x=5;}
```
Ты просто открываешь терминал и пишешь:
```bash
cargo fmt
```
И магия! Твой код в файле `main.rs` мгновенно переписывается в идеальный, красивый вид:
```rust
fn main() {
    println!("Привет");
    let x = 5;
}
```
**Золотое правило:** перед тем как показать кому-то свой код, всегда запускай `cargo fmt`. Большинство современных редакторов кода (VS Code, RustRover) делают это автоматически при каждом сохранении файла.

#### 3. Clippy: Твой строгий, но справедливый наставник

Компилятор Rust ловит критические ошибки (например, когда программа может упасть). Но код может быть технически рабочим, однако написанным неуклюже, некрасиво или неэффективно. 

Для этого в Rust есть встроенный линтер (анализатор кода) под названием **Clippy** (названный в честь скрепки-помощника из старого Microsoft Office, только этот помощник реально полезный). 

Представь, что у тебя за плечом стоит Senior-разработчик с многолетним опытом. Как только ты пишешь что-то странное, он хлопает тебя по плечу и говорит: *"Слушай, это работает, но в Rust так не принято. Сделай вот так, будет короче и быстрее"*.

**Как его вызвать?**
```bash
cargo clippy
```

**Пример из жизни:**
Допустим, ты проверяешь, является ли значение истинным, и пишешь так (пока не обращай внимания на синтаксис переменных, мы разберем его в следующей главе):
```rust
let is_active = true;

// Неопытный подход
if is_active == true {
    println!("Активно!");
}
```
Компилятор пропустит это. А вот `cargo clippy` выдаст тебе вежливое предупреждение:
*"Эй, `is_active` уже хранит в себе истину или ложь. Тебе не нужно сравнивать его с `true`. Просто напиши `if is_active { ... }`. Это более идиоматично (по-растовски)."*

---

**Резюме:**

С этого момента и до конца обучения (и в твоей будущей карьере) твой цикл разработки будет выглядеть так:
1. Пишем код в `src/main.rs`.
2. Запускаем `cargo check`, чтобы убедиться, что нет критических ошибок.
3. Запускаем `cargo clippy`, чтобы узнать, можно ли написать этот код лучше.
4. Запускаем `cargo fmt`, чтобы навести красоту.
5. Запускаем `cargo run`, чтобы увидеть результат работы!
