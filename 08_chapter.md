### Глава 8. Владение и Заимствование (Ownership & Borrowing)

В прошлой главе мы узнали, что динамические данные хранятся на гигантском складе (в Куче). Главная проблема всех языков программирования — как следить за этим складом. Если два человека одновременно попытаются изменить одну коробку, данные сломаются. Если попытаться удалить коробку дважды, программа упадет. 

Rust решает это с помощью системы **Владения (Ownership)**.

#### 1. Три золотых правила Владения

У Владения есть всего три правила, которые компилятор проверяет на этапе сборки:
1.  Каждое значение в Rust имеет переменную, которая называется его **Владельцем**.
2.  В любой момент времени может быть **только один** Владелец.
3.  Когда Владелец выходит из области видимости (закрывается фигурная скобка `{}`), значение удаляется со склада.

Давай посмотрим, как работает **Правило №2 (Только один владелец)** на практике.

Представь, что у тебя есть физическая книга (уникальный объект в Куче). Если ты передашь эту книгу другу, у тебя ее больше нет. Ты не можешь ее читать. Это называется **Перемещение (Move)**.

```rust
fn main() {
    // Создаем динамическую строку (она лежит в Куче)
    let s1 = String::from("Моя любимая книга"); 

    // Мы отдаем строку переменной s2. Происходит ПЕРЕМЕЩЕНИЕ (Move)
    let s2 = s1; 

    // println!("Я читаю: {}", s1); // ОШИБКА КОМПИЛЯЦИИ! 
    // s1 больше не владеет этими данными. s1 "пуста" и инвалидирована.
    
    println!("Друг читает: {}", s2); // Это работает! s2 теперь новый владелец.
}
```
**Почему это гениально?** Если бы и `s1`, и `s2` владели одними данными, то при закрытии скобки `}` Rust попытался бы удалить эти данные из Кучи дважды. Это называется "ошибка двойного освобождения" (double free), и в C++ она приводит к критическим уязвимостям. Rust просто убивает эту проблему в зародыше: владелец один, значит удаление произойдет ровно один раз.

*(Примечание: Обычные числа типа `i32` или `bool`, которые полностью лежат на Стеке, не перемещаются, а просто быстро **копируются**. Поэтому `let a = 5; let b = a;` сработает без проблем, и обе переменные останутся живы. Это называется трейт `Copy`).*

#### 2. Заимствование (Borrowing): Как давать данные почитать

Постоянно передавать Владение туда-сюда очень неудобно. Представь, что ты хочешь дать другу прочитать абзац, а потом забрать книгу обратно. В коде это выглядело бы так: ты передал переменную в функцию, а функция в конце вернула ее тебе через `return`. Это мучение.

Вместо того чтобы отдавать книгу навсегда, мы можем дать ее **почитать (заимствовать)**. Для этого используются **Ссылки (References)**. Они обозначаются символом амперсанда **`&`**.

```rust
// Функция принимает не саму строку, а ССЫЛКУ на строку (&String)
fn calculate_length(text: &String) -> usize {
    text.len() 
    // текст можно читать, но когда функция закончится, 
    // данные в Куче не удалятся, потому что функция ими НЕ ВЛАДЕЕТ.
}

fn main() {
    let my_string = String::from("Rust");

    // Мы передаем только ссылку (&), даем данные "в аренду"
    let length = calculate_length(&my_string);

    // Ура! my_string все еще с нами, мы можем ее использовать!
    println!("Длина слова '{}' равна {}", my_string, length);
}
```

#### 3. Изменяемые ссылки (Mutable References)

Что если друг хочет не просто прочитать книгу, но и вписать туда заметку? Обычная ссылка `&` работает в режиме **"Только чтение"** (Read-Only). 
Чтобы разрешить редактирование, мы должны использовать **Изменяемую ссылку `&mut`**. При этом сама переменная-владелец тоже должна быть `mut`.

```rust
// Функция принимает ИЗМЕНЯЕМУЮ ссылку (&mut String)
fn add_exclamation(text: &mut String) {
    text.push_str("!!!"); // Добавляем текст в конец
}

fn main() {
    let mut my_message = String::from("Привет");

    // Выдаем изменяемую ссылку
    add_exclamation(&mut my_message); 

    println!("{}", my_message); // Выведет "Привет!!!"
}
```

#### 4. Главный закон Заимствования (Предотвращение Data Races)

Вот тут компилятор Rust превращается в очень строгого полицейского. У изменяемых ссылок есть одно жесткое ограничение:
**Ты можешь дать данные на изменение только КОМУ-ТО ОДНОМУ в конкретный момент времени.**

Представь, что Google Документ открыт у двоих людей, и они одновременно пытаются напечатать текст на одной и той же строке. Будет хаос (в программировании это называется Состояние гонки или *Data Race*).

Rust запрещает это на этапе компиляции:

```rust
fn main() {
    let mut s = String::from("Данные");

    let r1 = &mut s; // Выдали права на редактирование первому
    // let r2 = &mut s; // ОШИБКА КОМПИЛЯЦИИ! Нельзя выдать вторые права на редактирование!

    println!("{}", r1);
}
```

Но и это еще не всё. Rust запрещает **читать** данные, пока кто-то другой их **изменяет**.
Правило звучит так: **У тебя может быть либо ЛЮБОЕ количество неизменяемых ссылок (читателей), ЛИБО ровно одна изменяемая ссылка (писатель). Но не то и другое одновременно.**

```rust
fn main() {
    let mut s = String::from("Книга");

    let read1 = &s; // Читатель 1
    let read2 = &s; // Читатель 2
    // println!("Читают: {} и {}", read1, read2); // Это абсолютно легально

    // let write1 = &mut s; // ОШИБКА! Кто-то взял книгу почитать! 
    // Ты не можешь вырвать ее у них из рук и начать переписывать текст.
    
    // Внимание: как только read1 и read2 перестают использоваться в коде (например, 
    // после последнего println), Rust поймет, что "читатели ушли", 
    // и разрешит тебе создать изменяемую ссылку &mut.
}
```

#### 5. Висячие ссылки (Dangling References) и Время жизни

В языках вроде C часто бывает баг: функция создает локальные данные, возвращает на них ссылку, а потом функция завершается, и данные удаляются (Стек очищается). В итоге ссылка указывает в "никуда" — на мусор в памяти. Попытка прочитать по ней данные приведет к крашу.

В Rust такое физически невозможно:

```rust
fn dangle() -> &String { // Мы обещаем вернуть ссылку на строку
    let s = String::from("hello"); // Строка создается внутри функции

    &s // Мы возвращаем ссылку на нее
} // ЗДЕСЬ s выходит из области видимости и удаляется! 
  // Rust увидит это на этапе компиляции и откажется собирать программу.
  // Ошибка: "эта функция возвращает ссылку на данные, которые были удалены".
```
Чтобы это починить, нужно вернуть саму строку (передать Владение), а не ссылку: `fn no_dangle() -> String`.

---

**Резюме:**
*   **Владение:** Данные принадлежат только одной переменной. Передал переменную = отдал навсегда (Move).
*   **Ссылки (`&`):** Дают почитать данные без передачи владения. Можно плодить сколько угодно читателей.
*   **Изменяемые ссылки (`&mut`):** Дают права на редактирование. Если есть писатель — других писателей и читателей быть не может.
*   Компилятор строго следит за тем, чтобы ссылки никогда не указывали на удаленные данные.
