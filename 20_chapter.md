### Глава 20. Макросы (Метапрограммирование)

В первых главах мы познакомились с макросом `println!` и макросом `vec!`. Ты мог заметить, что мы всегда ставим восклицательный знак `!`, когда их вызываем. 

**Зачем они вообще нужны? Почему нельзя было сделать обычную функцию `println()`?**
Дело в том, что обычные функции в Rust имеют строгие правила:
1. Они принимают строго фиксированное количество аргументов. Ты не можешь написать функцию, которая иногда принимает один аргумент, а иногда пять.
2. Они работают с конкретными типами данных (или с заранее описанными дженериками).

А макрос `println!("{} {} {}", a, b, c)` может принимать сколько угодно аргументов! 

Макросы — это программы, которые запускаются **до** того, как твой код начнет компилироваться. Они читают твой исходный код, видят вызов макроса, генерируют на его месте огромную "простыню" обычного, скучного кода на Rust, и только потом компилятор начинает свою проверку.


В Rust есть два абсолютно разных вида макросов: Декларативные и Процедурные.

#### 1. Декларативные макросы (`macro_rules!`)

Это самый частый вид макросов. Они работают по принципу сопоставления с образцом (как `match`, который мы учили в 6 главе), но они проверяют не значения переменных, а **синтаксис самого кода**.

Давай напишем свой собственный макрос для создания вектора. Назовем его `my_vec!`. Мы хотим, чтобы при вызове `my_vec![1, 2, 3]` макрос сам написал код создания пустого вектора и три раза вызвал метод `.push()`.

```rust
// Ключевое слово macro_rules! начинает создание декларативного макроса
macro_rules! my_vec {
    
    // Это "ветка" паттерна. Мы описываем, как должен выглядеть код внутри скобок макроса.
    // Синтаксис выглядит как заклинание, давай разберем его по частям:
    // $( ... )* - означает "повторить то, что внутри скобок, НОЛЬ или более раз"
    // ,         - означает "элементы должны быть разделены запятой"
    // $x:expr   - означает "захвати кусок кода (выражение - expr) и назови его $x"
    ( $( $x:expr ),* ) => {
        {
            let mut temp_vec = Vec::new();
            
            // Этот блок $( ... )* заставит макрос сгенерировать 
            // строку temp_vec.push($x); для КАЖДОГО захваченного элемента!
            $(
                temp_vec.push($x);
            )*
            
            // Возвращаем готовый вектор из блока кода
            temp_vec
        }
    };
}

fn main() {
    // Вызываем наш макрос
    let numbers = my_vec![10, 20, 30];
    
    // НЕВИДИМО ДЛЯ НАС, ПЕРЕД КОМПИЛЯЦИЕЙ, макрос заменит строчку выше на этот код:
    // let numbers = {
    //     let mut temp_vec = Vec::new();
    //     temp_vec.push(10);
    //     temp_vec.push(20);
    //     temp_vec.push(30);
    //     temp_vec
    // };
    
    println!("Наш вектор: {:?}", numbers);
}
```

Это невероятно мощный инструмент для избавления от рутины. Если тебе нужно написать 50 похожих блоков кода, ты просто пишешь один макрос, и компилятор разворачивает его за тебя.

#### 2. Процедурные макросы

Если декларативные макросы (`macro_rules!`) — это просто продвинутый "поиск и замена", то **Процедурные макросы** — это полноценные программы на Rust, которые манипулируют кодом. 

Они принимают на вход "Поток токенов" (грубо говоря, слова твоего кода), анализируют их с помощью функций, и выдают обратно новый "Поток токенов". 

Писать процедурные макросы довольно сложно — они должны находиться в отдельном специальном крейте (проекте) с настройкой `proc-macro = true` в `Cargo.toml`. Поэтому мы не будем писать их с нуля прямо сейчас, но ты должен уметь их различать и пользоваться ими (ты будешь использовать чужие процедурные макросы каждый день).

Они делятся на три вида:

**А. Custom `#[derive]` (Пользовательский вывод трейтов)**
Помнишь, как в 11 главе мы добавили `#[derive(Debug)]` над структурой, и компилятор сам написал для нас метод вывода на экран? Это и есть процедурный макрос!
Он читает имена полей твоей структуры (например, `name`, `age`) и автоматически генерирует для них блок `impl Debug for User { ... }`.
Часто используется в библиотеке `Serde` для мгновенного превращения структур в JSON:
```rust
#[derive(Serialize, Deserialize)] // Вжух, и структура умеет превращаться в JSON!
struct User {
    name: String,
}
```

**Б. Атрибутоподобные макросы (Attribute-like)**
Они вешаются над любой функцией или структурой и могут полностью переписать то, что находится под ними.
Мы видели это в прошлой главе, когда запускали асинхронный движок Tokio!
```rust
#[tokio::main] // Этот макрос заглатывает твою функцию main и переписывает её
async fn main() {
    // ...
}
```
Или, например, в веб-фреймворках так задают пути для страниц:
```rust
#[route(GET, "/users")] // Макрос сам сгенерирует весь код для привязки ссылки к функции
fn get_users() {
    // ...
}
```

**В. Макросы, похожие на функции (Function-like)**
Выглядят так же, как декларативные (с восклицательным знаком), но внутри работают гораздо сложнее. Они могут парсить вообще любой текст!
Например, макрос для написания SQL-запросов:
```rust
// Этот макрос прямо во время КОМПИЛЯЦИИ проверит, 
// правильный ли SQL ты написал, и существует ли колонка 'id' в твоей базе данных!
let sql = sql!("SELECT * FROM users WHERE id = 1"); 
```

---

**Резюме:**
*   Макросы — это код, который пишет код перед сборкой программы (метапрограммирование).
*   Они нужны для ситуаций, когда возможностей обычных функций и дженериков не хватает (например, нужно неизвестное количество аргументов или генерация больших кусков шаблонного кода).
*   **Декларативные макросы (`macro_rules!`)** — ищут совпадения по паттерну и вставляют куски кода.
*   **Процедурные макросы** — это мощные плагины для компилятора (`#[derive]`, `#[tokio::main]`), которые читают твой код и переписывают его по сложным алгоритмам.
