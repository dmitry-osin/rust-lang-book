### Глава 10. Обобщенное программирование (Generics)

Представь, что ты работаешь на заводе, который выпускает картонные коробки. Тебе заказали сделать коробку для яблок. Ты берешь чертеж и пишешь на нем "Коробка для Яблок". Потом приходит заказ на коробку для книг. Ты берешь новый чертеж, срисовываешь ту же самую коробку, но пишешь на ней "Коробка для Книг". 
Это глупо, правда? Гораздо умнее нарисовать один универсальный чертеж и оставить пустое место: "Коробка для [ВСТАВЬ НУЖНОЕ]".

В программировании это пустое место называется **Обобщенным типом (Generic Type)**. Обычно его обозначают одной большой буквой — **`T`** (от слова Type).

#### 1. Generics в функциях

Допустим, мы хотим написать функцию, которая просто возвращает то, что ей передали (очень глупая функция, но отличный пример).

Если мы пишем без дженериков, нам придется создавать отдельную функцию для каждого типа:
```rust
fn return_number(item: i32) -> i32 { item }
fn return_string(item: String) -> String { item }
fn return_bool(item: bool) -> bool { item }
```

А теперь используем магию дженериков:
Мы говорим компилятору: *"Эта функция работает с неким неизвестным типом. Давай назовем его `T`. Она принимает параметр типа `T` и возвращает результат типа `T`"*.

```rust
// <T> сразу после имени функции — это объявление: "Эй, я буду использовать дженерик T!"
fn return_anything<T>(item: T) -> T {
    item
}

fn main() {
    let a = return_anything(5);            // Компилятор видит 5 и понимает: T = i32
    let b = return_anything(String::from("Привет")); // Здесь компилятор понимает: T = String
}
```
Мы написали код один раз, а работает он для *любых* типов!

#### 2. Generics в структурах

Точно так же мы можем создавать универсальные структуры (чертежи). 
Вспомним структуру `Point` (Точка на графике) из 5-й главы. Что если мы хотим, чтобы координаты точки иногда были целыми числами (`i32`), а иногда дробными (`f64`)?

```rust
// Говорим, что структура Point зависит от типа T
struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let integer_point = Point { x: 5, y: 10 };       // Здесь T становится i32
    let float_point = Point { x: 1.5, y: 4.0 };    // Здесь T становится f64
    
    // let bad_point = Point { x: 5, y: 4.0 }; 
    // ОШИБКА! x - это целое, значит T = i32. 
    // Но y тоже должен быть T (i32), а мы передаем дробное (f64).
}
```

А что если мы **хотим**, чтобы `x` и `y` могли быть разных типов? Нет проблем! Просто используем две разные буквы для "пустых мест" — например, `T` и `U`.

```rust
struct FlexiblePoint<T, U> {
    x: T,
    y: U,
}

fn main() {
    // x будет i32, а y будет f64. Всё абсолютно легально!
    let mixed_point = FlexiblePoint { x: 5, y: 4.0 }; 
}
```

#### 3. Возвращаемся к Option и Result

Теперь ты полностью понимаешь, как устроены `Option` и `Result` из стандартной библиотеки Rust!

```rust
// Option - это просто перечисление с одним "пустым местом" T для любого значения
enum Option<T> {
    Some(T),
    None,
}

// Result - это перечисление с двумя "пустыми местами": 
// T для значения успеха, и E (Error) для значения ошибки
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```
Именно поэтому `Result` может хранить строку в случае успеха и системную ошибку в случае провала.

#### 4. Generics в методах (реализация поведения)

Когда мы хотим добавить методы нашей универсальной структуре с помощью блока `impl`, мы тоже должны указать букву `T`, чтобы компилятор понял, к какому именно "чертежу" мы пишем методы.

```rust
struct Point<T> {
    x: T,
    y: T,
}

// Внимание на синтаксис: impl<T> значит "я сейчас буду писать методы для универсального типа"
// Point<T> значит "эти методы принадлежат структуре Point"
impl<T> Point<T> {
    // Метод, который возвращает ссылку на координату X
    fn get_x(&self) -> &T {
        &self.x
    }
}
```

Но магия Rust на этом не заканчивается. Мы можем написать метод, который будет доступен **только для точек определенного типа**!

```rust
// Этот блок impl НЕ имеет <T> после слова impl. 
// Он строго привязан к Point, где вместо T подставили f32.
impl Point<f32> {
    // Метод для вычисления расстояния от центра координат.
    // Работает только с дробными числами (f32), потому что у целых чисел нет метода квадратного корня sqrt().
    fn distance_from_origin(&self) -> f32 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}
```
Если ты создашь точку с целыми числами (`Point { x: 5, y: 10 }`), метод `distance_from_origin` у нее даже не появится в подсказках! Это невероятно мощный инструмент для контроля логики.

#### 5. Производительность: Мономорфизация (Почему это бесплатно?)



В некоторых языках использование универсальных типов сильно замедляет программу, потому что компьютеру приходится "на лету" разбираться, с каким типом он сейчас работает.

В Rust дженерики **абсолютно бесплатны** (zero-cost abstraction). 
Как инспектору-компилятору это удается? Он использует процесс, который называется **Мономорфизация** (Monomorphization - превращение в единую форму).

Когда ты пишешь код с дженериками:
```rust
let a = return_anything(5); // i32
let b = return_anything(1.5); // f64
```
Во время компиляции (превращения кода в программу) Rust находит все места, где ты использовал функцию. Он видит, что ты использовал её для `i32` и для `f64`. 
Тогда он **невидимо для тебя копирует твою функцию дважды**, заменяя `T` на конкретные типы:

```rust
// То, что делает компилятор под капотом (ты этого не пишешь):
fn return_anything_i32(item: i32) -> i32 { item }
fn return_anything_f64(item: f64) -> f64 { item }
```

В результате в готовой программе вообще нет никаких неизвестных типов `T`. Там лежат жестко прописанные, сверхбыстрые функции для конкретных типов. Ты получаешь удобство при написании кода без малейшей потери скорости при его работе!

---

**Резюме:**
*   **Дженерики (Generics, `<T>`)** — это способ оставить "пустое место" для типа данных в функциях, структурах или перечислениях.
*   Они позволяют писать универсальный код (принцип DRY — Don't Repeat Yourself).
*   Блоки `impl` позволяют писать общие методы для всех вариаций `T`, либо специфичные методы только для конкретных типов (например, только для `f32`).
*   Благодаря **мономорфизации**, дженерики не замедляют работу программы ни на наносекунду.
