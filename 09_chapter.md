### Глава 9. Обработка ошибок

#### 1. Неисправимые ошибки: Макрос panic!

Иногда в программе происходит нечто настолько ужасное, что продолжать работу небезопасно или бессмысленно. Например, ты пишешь программу для управления кардиостимулятором, и датчик сердцебиения внезапно возвращает отрицательное число. В такой ситуации лучше экстренно остановить всё, чем продолжать работать с бредовыми данными.

Для таких случаев в Rust есть макрос **`panic!`** (паника). 

Когда происходит паника, программа немедленно печатает сообщение об ошибке, очищает за собой память (убирает все переменные со Стека и из Кучи) и завершает работу.

```rust
fn main() {
    // Мы можем вызвать панику вручную
    // panic!("Всё сломалось, датчики сошли с ума!");

    let numbers = [1, 2, 3];
    
    // А здесь панику вызовет сам Rust, так как мы обращаемся к 99-му элементу 
    // в массиве, где всего 3 элемента. Это защитный механизм.
    println!("{}", numbers[99]); 
}
```
*Правило:* Используй панику только тогда, когда программа оказалась в состоянии, которое невозможно было предвидеть, и восстановиться после этого нельзя.

#### 2. Исправимые ошибки: Тип Result

В 99% случаев ошибки можно исправить. Например, пользователь ввел текст вместо числа, или программа не смогла найти файл на диске. Это нормальное явление, из-за которого программа не должна «падать».

Для исправимых ошибок Rust использует встроенное перечисление (Enum), которое называется **`Result`** (Результат). 



Под капотом оно выглядит так:
```rust
enum Result<T, E> { // T и E - это "любые типы", мы изучим их в следующей главе
    Ok(T),  // Вариант Ok хранит успешный результат типа T
    Err(E), // Вариант Err хранит данные об ошибке типа E
}
```

Представь, что ты заказываешь товар в интернет-магазине. Функция возвращает тебе коробку `Result`. 
*   Внутри может лежать заветный товар — это вариант **`Ok(товар)`**.
*   Либо там лежит письмо с извинениями "Товара нет на складе" — это вариант **`Err(письмо)`**.

Давай попробуем перевести строку в число. Встроенный метод `parse` возвращает именно `Result`:

```rust
fn main() {
    let good_input = "42";
    let bad_input = "сорок два";

    // Возвращается Result. Компилятор ЗАСТАВИТ нас его проверить.
    let result: Result<i32, _> = good_input.parse(); 

    // Как мы уже умеем, распаковываем коробку с помощью match
    match result {
        Ok(number) => println!("Ура, мы получили число: {}", number),
        Err(error) => println!("Ой, это не число! Детали: {}", error),
    }
}
```

#### 3. Ленивая распаковка: unwrap и expect

Писать `match` на каждый "чих" может быть утомительно, особенно если ты пишешь небольшой скрипт для себя и точно уверен, что ошибки быть не может.

Для ленивых в Rust есть два метода: **`unwrap()`** (распаковать) и **`expect()`** (ожидать).

Они говорят компилятору следующее: *"Достань значение из `Ok`. Но если там окажется `Err`, просто вызывай `panic!` и убивай программу"*.

```rust
fn main() {
    // unwrap() берет значение из Ok. Если там Err, программа падает со стандартной ошибкой.
    let number1: i32 = "100".parse().unwrap(); 

    // expect() делает то же самое, но позволяет написать понятное сообщение для паники
    let number2: i32 = "abc".parse().expect("Я ожидал, что здесь будет число!"); 
}
```
**Внимание, антипаттерн:** В серьезной (промышленной) разработке использование `unwrap()` считается плохим тоном (за исключением тестов). Хороший код никогда не должен паниковать из-за неверного ввода. Ошибки нужно обрабатывать изящно. И для этого есть специальный инструмент.

#### 4. Элегантная проброска ошибок: Оператор `?`

Представь, что ты пишешь функцию, которая должна открыть файл, прочитать из него текст и перевести его в число. На каждом этапе может быть ошибка. 

Писать вложенные `match` (так называемую "лестницу") — это ужасно:
```rust
// ТАК ПИСАТЬ НЕ НАДО (Громоздко)
use std::fs::File; // Подключаем модуль для работы с файлами

fn read_number_badly() -> Result<i32, std::io::Error> {
    let file_result = File::open("my_number.txt");
    
    let file = match file_result {
        Ok(f) => f,
        Err(e) => return Err(e), // Возвращаем ошибку наружу
    };
    
    // ... и так далее для каждого шага
    Ok(10)
}
```

Вместо этого Rust предлагает гениальный **оператор `?`** (знак вопроса). 

Он ставится в конце вызова функции, которая возвращает `Result`. 
Как он работает:
*   Если функция вернула **`Ok(значение)`**, оператор `?` просто достает это значение, и код идет дальше.
*   Если функция вернула **`Err(ошибка)`**, оператор `?` делает невидимый `return` и **сразу же возвращает эту ошибку из ТВОЕЙ функции** вызывающему коду.

Смотри, как красиво и чисто это выглядит:

```rust
use std::fs::File;
use std::io::Read;

// Наша функция возвращает Result. 
// В случае успеха вернем String, в случае провала - ошибку ввода/вывода (io::Error)
fn read_file_elegantly() -> Result<String, std::io::Error> {
    // Открываем файл. Если ошибка — выходим из функции и отдаем ошибку.
    // Если успех — кладем открытый файл в переменную f.
    let mut f = File::open("hello.txt")?; 
    
    let mut text = String::new();
    
    // Читаем содержимое в строку. Снова используем ?
    f.read_to_string(&mut text)?; 
    
    // Если мы дошли сюда, значит всё прошло гладко. 
    // Оборачиваем готовый текст в Ok и возвращаем.
    Ok(text) 
}

fn main() {
    match read_file_elegantly() {
        Ok(content) => println!("Содержимое файла: {}", content),
        Err(e) => println!("Не удалось прочитать файл: {}", e),
    }
}
```
*Важное правило:* Ты можешь использовать знак вопроса `?` **только внутри тех функций, которые сами возвращают `Result`** (или `Option`). Если функция `main` ничего не возвращает, ты не сможешь использовать там `?`.

#### 5. Обработка нескольких типов ошибок

Иногда в одной функции могут возникать ошибки абсолютно разных типов. Например, `File::open` возвращает `std::io::Error`, а парсинг строки возвращает `std::num::ParseIntError`. Оператор `?` попытается вернуть их, но в заголовке функции мы должны указать какой-то *один* тип возвращаемой ошибки.

Как быть? Для этого в Rust есть концепция "Объектов Трейтов". Мы глубоко изучим эту магию позже, но сейчас просто запомни универсальную конструкцию:

```rust
// Box<dyn std::error::Error> означает "Любая ошибка" (Универсальная коробка для ошибок)
fn do_many_things() -> Result<i32, Box<dyn std::error::Error>> {
    let mut file = std::fs::File::open("number.txt")?; // Ошибка чтения файла
    
    let mut content = String::new();
    std::io::Read::read_to_string(&mut file, &mut content)?;
    
    // Ошибка парсинга числа! Оператор ? автоматически запакует её в универсальную коробку.
    let number: i32 = content.trim().parse()?; 
    
    Ok(number)
}
```

---

**Резюме:**
*   В Rust нет скрытых Исключений (`try/catch`).
*   **`panic!`** — для фатальных ошибок, когда нужно экстренно остановить программу.
*   **`Result<T, E>`** — для нормальных, ожидаемых ошибок. Это коробка, в которой лежит либо успех (`Ok`), либо проблема (`Err`).
*   Не используй **`unwrap()`** и **`expect()`** в итоговом коде, они могут вызвать панику.
*   Оператор **`?`** — твой лучший друг. Он делает код чистым, автоматически распаковывая `Ok` или мгновенно пробрасывая `Err` на уровень выше.
