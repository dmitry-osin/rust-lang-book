### Глава 17. Умные указатели и Утечки памяти

#### 1. Что такое указатель и `Unsafe`-контекст

Обычный **указатель** — это просто переменная, которая хранит адрес в оперативной памяти (как номер ячейки на складе). В Rust есть так называемые "сырые" указатели (`*const T` и `*mut T`). 

Но чтобы прочитать данные по сырому указателю, нужно войти в **`unsafe` (небезопасный) контекст**.

```rust
fn main() {
    let mut num = 5;
    
    // Создаем сырые указатели (это безопасно, мы просто записали адреса)
    let r1 = &num as *const i32;
    let r2 = &mut num as *mut i32;

    // ВНИМАНИЕ: Зона без гарантий компилятора!
    unsafe {
        // Только внутри блока unsafe мы можем "разыменовать" сырой указатель (знак *)
        println!("r1: {}", *r1);
        *r2 = 10;
        println!("r2: {}", *r2);
    }
}
```
**Зачем нужен `unsafe`?** Внутри этого блока Rust отключает Borrow Checker. Это позволяет тебе делать вещи, которые компилятор не может проверить (например, общаться с кодом на C/C++ или писать драйверы для железа). 
*Золотое правило разработчика:* Никогда не пиши `unsafe`, если можешь решить задачу обычным (безопасным) кодом.

Для безопасной работы с памятью в Rust придумали **Умные указатели**. Это структуры, которые работают как указатели, но обладают интеллектом (через реализацию трейтов `Deref` и `Drop`). Мы уже с ними знакомы: `String` и `Vec<T>` — это умные указатели!

#### 2. Выделение памяти в куче: `Box<T>`

`Box` (Коробка) — это самый простой умный указатель.  Он делает ровно одну вещь: **принудительно** кладет твои данные в Кучу (на огромный склад), а на Стеке (в быстром доступе) оставляет только маленькую квитанцию-указатель.

**Зачем это нужно?**
Самый частый случай применения `Box` — создание **рекурсивных типов**.
Представь, что ты хочешь создать "Список", где каждый элемент хранит значение и *следующий* элемент списка.

```rust
// ОШИБКА КОМПИЛЯЦИИ! 
// Компилятор должен знать размер структуры List, чтобы выделить для неё место.
// Но List содержит внутри себя другой List, который содержит третий List... 
// Это бесконечная матрешка! Размер вычислить невозможно.
// enum List {
//     Cons(i32, List),
//     Nil,
// }
```

Решение: Упаковать внутренний `List` в `Box`! Размер самого `Box` всегда известен (это просто адрес в памяти, например 64 бита), а реальные данные будут лежать в Куче.

```rust
// ТЕПЕРЬ ВСЁ РАБОТАЕТ!
enum List {
    Cons(i32, Box<List>), // Храним не саму матрешку, а УКАЗАТЕЛЬ на неё в Куче
    Nil,
}

use List::{Cons, Nil};

fn main() {
    // Создаем список: 1 -> 2 -> 3 -> Конец
    let my_list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
}
```

#### 3. Подсчет ссылок: `Rc<T>` (Разрешаем несколько владельцев)

Бывают ситуации, когда данные должны иметь **несколько равноправных владельцев**. 
Представь телевизор в гостиной студенческого общежития. У него нет одного хозяина. Им владеют все соседи по комнате. Телевизор (память) нужно выбросить только тогда, когда съедет **последний** сосед.

В Rust для этого есть **`Rc<T>`** (Reference Counted — Подсчет ссылок). 

Он работает просто: внутри него лежит счетчик. Когда ты создаешь клона `Rc`, данные в памяти не копируются! Просто счетчик увеличивается на 1. Когда клон выходит из области видимости, счетчик уменьшается. Когда счетчик равен 0, данные удаляются.

```rust
use std::rc::Rc;

fn main() {
    // Создаем данные, оборачиваем в Rc. Счетчик владельцев = 1.
    let tv = Rc::new(String::from("Плазменный телевизор"));
    println!("Владельцев: {}", Rc::strong_count(&tv)); // Выведет 1

    {
        // Rc::clone НЕ копирует сам телевизор. Он создает новый указатель на него 
        // и увеличивает счетчик на 1. Это происходит мгновенно.
        let roomate_1 = Rc::clone(&tv);
        println!("Владельцев: {}", Rc::strong_count(&tv)); // Выведет 2
        
        let roomate_2 = Rc::clone(&tv);
        println!("Владельцев: {}", Rc::strong_count(&tv)); // Выведет 3
        
    } // ЗДЕСЬ roomate_1 и roomate_2 выходят из области видимости. Счетчик падает до 1.

    println!("Владельцев: {}", Rc::strong_count(&tv)); // Выведет 1. Телевизор еще жив!
} // ЗДЕСЬ выходит tv. Счетчик становится 0. Память очищается.
```
*Важно:* `Rc` позволяет иметь несколько владельцев, но они имеют права **только на чтение**. Как же изменить данные, если у них несколько владельцев?

#### 4. Внутренняя изменяемость: `RefCell<T>`

Если ты попытаешься изменить данные, на которые ссылается несколько переменных, строгий Borrow Checker остановит тебя на этапе компиляции. Он скажет: "Я не уверен, что это безопасно".

Но иногда ты как программист *знаешь*, что твой код безопасен, просто компилятор недостаточно умен, чтобы это понять.
Для этого придуман **`RefCell<T>`**. 

Он реализует паттерн "Внутренняя изменяемость" (Interior Mutability). Он позволяет тебе изменять данные даже тогда, когда сама переменная `RefCell` объявлена как неизменяемая (`let`, а не `let mut`).

Как это работает? `RefCell` переносит проверку правил заимствования **с этапа компиляции на этап работы программы (runtime)**. 

```rust
use std::cell::RefCell;

fn main() {
    // Обрати внимание: переменная data НЕ mut!
    let data = RefCell::new(5);

    // borrow_mut() просит у RefCell изменяемую ссылку.
    // RefCell внутри себя ставит галочку: "Выдана изменяемая ссылка".
    *data.borrow_mut() += 10;
    
    println!("Данные: {}", data.borrow()); // Выведет 15
}
```
**В чем подвох?** Если ты попытаешься обмануть `RefCell` и взять *две* изменяемые ссылки одновременно:
```rust
let mut ref1 = data.borrow_mut();
let mut ref2 = data.borrow_mut(); // ПРОГРАММА ЗАПАНИКУЕТ (КРАШ) ПРЯМО ВО ВРЕМЯ РАБОТЫ!
```
Это компромисс. Ты обходишь строгий компилятор, но рискуешь получить панику в рантайме.

**Святая связка `Rc<RefCell<T>>`:**
Объединив эти два указателя, мы получаем Святой Грааль гибкости: **Значение, у которого несколько владельцев, и ЛЮБОЙ из них может изменять это значение**. (Это очень часто используется для реализации деревьев, графов и двусвязных списков).

#### 5. Утечки памяти в безопасном Rust (Циклические ссылки)

Долгое время считалось, что если язык не позволяет работать с памятью напрямую, то утечек памяти в нем быть не может. В Rust это не так! Используя мощь `Rc` и `RefCell`, мы можем обхитрить сами себя и создать "вечный двигатель" в памяти. 

Допустим, у нас есть Узел A и Узел B.
Если мы скажем: "Узел A владеет Узлом B, а Узел B владеет Узлом A", их счетчики ссылок (`Rc`) всегда будут минимум равны 1! Они никогда не опустятся до нуля, и память никогда не очистится. Это называется **Циклическая ссылка (Reference Cycle)**.

```rust
use std::rc::Rc;
use std::cell::RefCell;

// Узел содержит значение и ссылку на следующий узел
struct Node {
    value: i32,
    next: RefCell<Option<Rc<Node>>>,
}

fn main() {
    let node_a = Rc::new(Node {
        value: 1,
        next: RefCell::new(None),
    });

    let node_b = Rc::new(Node {
        value: 2,
        next: RefCell::new(Some(Rc::clone(&node_a))), // B указывает на A
    });

    // Изменяем A, чтобы он указывал на B! Замыкаем круг!
    *node_a.next.borrow_mut() = Some(Rc::clone(&node_b));

    // Если мы раскомментируем следующую строку, программа зависнет навсегда, 
    // пытаясь распечатать A -> B -> A -> B...
    // println!("A: {:?}", node_a); 
    
    // В конце main() Rust попытается удалить a и b, но их счетчики равны 2. 
    // Они упадут до 1 и останутся в Куче навсегда. УТЕЧКА ПАМЯТИ!
}
```

**Как этого избежать? `Weak<T>` (Слабая ссылка)**
Чтобы разорвать порочный круг, в Rust придумали `Weak` (слабый) указатель. В отличие от `Rc` (сильного), он **не защищает данные от удаления**. 

Представь дерево (папки на компьютере).
Родительская папка **владеет** дочерними папками (использует `Rc`). Если удалить родителя, дети тоже должны удалиться.
Но если дочерней папке нужно знать, кто её родитель, она должна хранить на него **слабую ссылку** (`Weak`). Она может спросить: "Мой родитель еще жив?", но она не мешает системе удалить родителя.

---

**Резюме:**
*   **Сырые указатели (`*const T`) и `unsafe`** — темная магия, которую мы используем только в крайних случаях (например, при общении с C/C++).
*   **`Box<T>`** — выделяет память в Куче. Нужен для рекурсивных типов и передачи огромных массивов данных без их копирования на Стеке.
*   **`Rc<T>`** — позволяет иметь несколько владельцев (только для чтения). Считает ссылки.
*   **`RefCell<T>`** — позволяет изменять неизменяемое, но проверяет правила заимствования прямо во время работы программы (риск паники!).
*   **`Rc<RefCell<T>>`** — мощнейшее комбо для создания графов и сложных структур, где все могут изменять всё.
*   **`Weak<T>`** — спасает от циклических утечек памяти, позволяя ссылаться на данные, не владея ими.
