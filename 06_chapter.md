### Глава 6. Могущество сопоставления с образцом (Pattern Matching)

В других языках программирования есть конструкция `switch` — она берет переменную и прогоняет её через список: "ты равна 1? а 2? а 3?". 

В Rust вместо нее используется **`match`** (сопоставлять). Это не просто проверка на равенство. Это полноценный сортировочный центр. `match` может заглядывать *внутрь* структур и перечислений, доставать оттуда данные и заставлять тебя обработать абсолютно все возможные варианты. 

#### 1. Конструкция match: Сортировочный центр

Давай начнем с простого примера. Возьмем перечисление со сторонами света.

```rust
enum Direction {
    North,
    South,
    East,
    West,
}

fn main() {
    let my_direction = Direction::North;

    // match берет значение и прогоняет его по "рукавам" (веткам)
    match my_direction {
        Direction::North => println!("Идем на север!"),
        Direction::South => println!("Идем на юг!"),
        Direction::East => println!("Идем на восток!"),
        Direction::West => println!("Идем на запад!"),
    }
}
```

**Строгость Rust:** Что если мы забудем написать ветку для `West`? Компилятор выдаст ошибку! Он скажет: *"Эй, ты покрыл не все варианты. А что мне делать, если придет West?"*. Это потрясающая защита от багов: если ты добавишь новый вариант в `enum`, компилятор сам покажет все места в коде, где ты забыл его обработать.

#### 2. Распаковка данных с помощью match

Теперь магия. Помнишь перечисление `WebEvent` из прошлой главы, где варианты хранили данные? `match` умеет их извлекать!

```rust
enum WebEvent {
    PageLoad,
    KeyPress(char),
    Click { x: i64, y: i64 },
}

fn main() {
    let event = WebEvent::Click { x: 250, y: 140 };

    match event {
        WebEvent::PageLoad => println!("Страница загрузилась"),
        // Мы "захватываем" символ из KeyPress в переменную c
        WebEvent::KeyPress(c) => println!("Нажата клавиша: {}", c),
        // Мы "захватываем" координаты x и y из Click
        WebEvent::Click { x, y } => println!("Клик мышкой по координатам x:{}, y:{}", x, y),
    }
}
```
Это и есть **сопоставление с образцом (Pattern Matching)**. Rust смотрит: "Ага, `event` выглядит как `Click`. Значит, я возьму его внутренности и положу их в переменные `x` и `y`, чтобы код справа от `=>` мог с ними работать".

#### 3. Распаковка Option (Безопасное извлечение подарка)

В прошлой главе мы выяснили, что переменная типа `Option` — это коробка, в которой может быть либо значение (`Some`), либо пустота (`None`). Сложить `Option` с обычным числом нельзя. Как же достать число? Через `match`!

```rust
fn main() {
    let some_number = Some(5);
    // let empty_number: Option<i32> = None;

    // match ЗАСТАВЛЯЕТ нас обработать случай, когда внутри пусто (None)
    match some_number {
        Some(value) => {
            println!("Ура, внутри число: {}", value);
            // Здесь с value можно делать что угодно, например: value + 10
        },
        None => println!("Упс, коробка пуста!"),
    }
}
```
Именно так Rust защищает тебя от падений программы. Ты физически не сможешь добраться до значения, не написав инструкцию на случай, если там `None`.

#### 4. Продвинутые паттерны и Range

`match` умеет работать не только с `enum`, но и с обычными числами, используя диапазоны (`Range`) и группировку паттернов.

```rust
fn main() {
    let age = 15;

    match age {
        0 => println!("Только родился!"),
        1 | 2 | 3 => println!("Малыш"), // Символ | означает "ИЛИ"
        4..=12 => println!("Ребенок"),  // Диапазон от 4 до 12 включительно
        13..=19 => println!("Подросток"),
        _ => println!("Взрослый"),      // Нижнее подчеркивание _
    }
}
```
**Что такое `_` (нижнее подчеркивание)?** 
Это паттерн "всё остальное" (catch-all). Поскольку чисел миллиарды, мы не можем перечислить их все в `match`. Мы описываем нужные нам диапазоны, а для всех остальных случаев ставим `_`. Если мы этого не сделаем, строгий компилятор снова выдаст ошибку, требуя исчерпывающего покрытия.

#### 5. Синтаксический сахар: if let

Иногда `match` бывает слишком громоздким. Представь, что у тебя есть `Option`, и ты хочешь выполнить код **только если** внутри есть значение (`Some`). На `None` тебе абсолютно плевать, ты не хочешь ничего делать.

Писать `match` с пустой веткой `_ => ()` некрасиво:
```rust
let my_value = Some(100);

// Громоздко
match my_value {
    Some(x) => println!("Значение: {}", x),
    _ => (), // Ничего не делаем
}
```

Для таких случаев в Rust придумали **`if let`**. Это как снайперский `match`, который стреляет только по одному конкретному паттерну.

```rust
let my_value = Some(100);

// Читается так: "ЕСЛИ мы можем распаковать my_value по шаблону Some(x), 
// ТО выполнить этот блок кода"
if let Some(x) = my_value {
    println!("Значение: {}", x);
} 
// Если внутри None, программа просто пойдет дальше, ничего не сказав
```

#### 6. Цикл while let

Аналогично работает `while let`. Он будет выполнять цикл до тех пор, пока паттерн совпадает. Это очень часто используется, когда мы достаем элементы из списка, пока они не кончатся (когда список пустеет, метод возвращает `None`).

```rust
// У нас есть вектор (динамический массив) чисел. 
let mut numbers = vec![1, 2, 3];

// Метод pop() забирает последнее число из вектора и возвращает его в виде Some(число).
// Если вектор пуст, pop() возвращает None.

// Читается так: "ПОКА мы можем доставать Some(n) из numbers.pop(), печатай число"
while let Some(n) = numbers.pop() {
    println!("Достали: {}", n);
}
// Как только pop() вернет None, цикл тихо завершится.
```

---

**Резюме:**
*   **`match`** — это мощнейший сортировочный узел, который проверяет значения, разбирает структуры и `enum` на запчасти, и требует, чтобы ты обработал *каждый* возможный сценарий.
*   Символ **`_`** используется в `match`, чтобы сказать "для всех остальных случаев".
*   **`if let`** — это короткий способ написать `match`, когда нас интересует только один вариант (например, успешно извлеченный `Some`), а на остальные мы хотим закрыть глаза.
