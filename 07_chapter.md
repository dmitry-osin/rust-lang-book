### Глава 7. Устройство памяти. Стек и Куча

Когда твоя программа запускается, ей нужно место для хранения данных (переменных). Компьютер выделяет для этого оперативную память. В Rust (как и во многих других системных языках) память делится на две абсолютно разные зоны: **Стек (Stack)** и **Кучу (Heap)**.

Давай разберем их на простых примерах из реальной жизни.

#### 1. Стек (Stack): Идеальный шкаф с одинаковыми ящиками

Представь себе стопку тарелок в кафе. Ты можешь положить новую тарелку только на самый верх. И взять тарелку ты тоже можешь только с самого верха. Ты не можешь вытащить тарелку из середины, не уронив остальные.

Это принцип **LIFO (Last In, First Out — Последним пришел, первым ушел)**. Именно так работает Стек. 

*   **Как это работает:** Когда ты создаешь переменную, данные кладутся "наверх" стека. Когда переменная больше не нужна, она снимается "сверху". 
*   **Главное правило Стека:** Чтобы положить данные в Стек, компилятор должен **точно знать их размер** еще до запуска программы.
*   **Что там хранится?** Все базовые типы, о которых мы говорили в Главе 3: числа (`i32`, `f64`), логические значения (`bool`), символы (`char`), кортежи и массивы из этих типов. Размер числа `i32` всегда равен 32 битам, он никогда не изменится.
*   **Скорость:** Стек невероятно быстрый. Компьютеру не нужно искать свободное место — он просто кладет данные на самый верх.

#### 2. Куча (Heap): Огромный склад без правил

А что делать, если мы хотим сохранить текст, который пользователь введет с клавиатуры? Мы не знаем заранее, напишет он "Привет" или поэму на 10 страниц "Война и мир". Размер этих данных может меняться во время работы программы. В Стек такое класть нельзя.

Для таких данных используется **Куча**. 

Представь, что Куча — это гигантский склад. 
1. Ты приходишь к кладовщику (операционной системе) и говоришь: *"Мне нужно место под огромный, но пока неизвестный объем текста"*. 
2. Кладовщик идет на склад, находит там достаточно большое свободное место, кладет туда твои данные и возвращает тебе **Квитанцию с номером ячейки**.
3. Эта квитанция называется **Указателем (Pointer)**.

И вот здесь происходит главная магия памяти:
Размер самого текста в Куче может быть любым (хоть 1 мегабайт, хоть гигабайт). Но размер *Квитанции* (указателя на ячейку памяти) — всегда фиксированный (например, 64 бита на современных компьютерах). 
Поэтому **сама квитанция хранится в быстром Стеке, а данные, на которые она указывает, лежат в медленной Куче**.

*   **Что там хранится?** Динамические данные, которые могут расти и уменьшаться. Самый яркий пример — тип `String` (динамическая строка) или векторы (динамические массивы), которые мы изучим позже.
*   **Скорость:** Куча работает медленнее. Компьютеру нужно потратить время, чтобы найти свободное место (выделить память), а потом, когда мы хотим прочитать данные, ему нужно сначала взять "квитанцию" из Стека и по ней "дойти" до нужного места на складе (в Куче).

#### 3. Контекст и область видимости (Scope)

Теперь, когда мы знаем, где хранятся данные, возникает вопрос: **а кто забирает тарелки со Стека и кто очищает место на складе в Куче?**

В языках вроде Java или Python есть "Сборщик мусора" (Garbage Collector) — специальный робот, который постоянно ездит по складу, ищет забытые вещи и выкидывает их. Это удобно, но робот потребляет ресурсы и тормозит программу.
В C++ программист должен сам руками писать команду "освободи память". Забыл написать — память утекла (утечка памяти).

Rust пошел третьим, гениальным путем. Он привязал жизнь переменных к их **Области видимости (Scope)**.

Область видимости в Rust задается фигурными скобками `{ }`. Это может быть тело функции, тело цикла или просто блок кода, который мы создали сами.

```rust
fn main() {
    // Переменной 'a' еще не существует

    { // Начало новой области видимости
        
        let a = 5; // Переменная 'a' родилась. Данные легли на Стек.
        
        let s = String::from("Привет"); // Переменная 's' родилась. 
        // Сам текст "Привет" лег в Кучу, а "Квитанция" легла на Стек.
        
        println!("{} {}", s, a);
        
    } // Конец области видимости! 
      // Здесь компилятор АВТОМАТИЧЕСКИ и мгновенно уничтожает 'a' и 's'.
      // Он снимает 'a' и квитанцию 's' со Стека, 
      // а также идет в Кучу и освобождает место от текста "Привет".

    // println!("{}", a); // ОШИБКА КОМПИЛЯЦИИ! 'a' больше не существует.
}
```

**Как Rust понимает, что нужно делать?**
Когда ты пишешь код, компилятор Rust анализирует твои фигурные скобки. На закрывающей скобке `}` он невидимо для тебя вставляет команды очистки памяти (вызывает специальную функцию `drop`). 
Тебе не нужно думать об очистке памяти! Rust уберет за тобой сам, в ту самую микросекунду, когда переменная выйдет из своей области видимости.

---

**Резюме:**
*   **Стек (Stack):** Стопка тарелок. Очень быстрый. Хранит данные с известным и фиксированным размером (числа, логические типы).
*   **Куча (Heap):** Огромный склад. Медленнее. Хранит данные, размер которых может меняться (динамические строки).
*   На Стеке хранятся сами данные (если они фиксированные) или "Квитанции/Указатели" на данные, лежащие в Куче.
*   **Область видимости `{}`:** Это жизненный цикл переменной. Когда закрывается фигурная скобка, переменная уничтожается, а ее память мгновенно и безопасно освобождается.
